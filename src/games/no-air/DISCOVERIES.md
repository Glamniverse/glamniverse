# M4 — The Pearl Hunt

Twenty original procedural 3D shells, seven fixed hidden pearls. Three instanced geometry families: seven rounded ribbed/scallop caps, seven elongated fan caps, six spiral-inspired whorled caps. Every shell has a stable ID, site, tint, orientation, ridge count and scale (approximately 20–40cm across). No downloaded assets, textures, dependencies or audio. Existing terrain and life are unchanged.

Placement: five accessible shelf sites, six sheltered/vegetation-adjacent sites, five slope/drop-off sites, four deeper sites. Ground height and orientation come from the actual existing terrain triangles at creation. All sites remain inside 95% of the swimming ellipse, outside inflated rock barriers and existing M2.1 botanical footprints. Tests swim an overhead approach then descend using the unmodified boundary resolver and verify unobstructed collection rays. Shells occupy the seabed, below the existing midwater animal routes. The starting spawn has no shell directly on it.

Either tracked controller's `xr-standard` primary trigger (button 0) collects on a fresh press. Menu must be closed and both swimming grips released. Reconnection, visibility loss, menu use and blocked input require release/re-arm. Aim within a 25cm radius of the shell centre, at most 2.6m along the controller ray. Selection performs a bounded terrain/rock/arch occlusion check. No persistent beam, HUD, new controller listeners or changes to swimming. A faint aimed-shell sheen provides local feedback.

Opening takes .55s, with a brief restrained surface shimmer. A pearl-bearing shell reveals its pearl from .18s; at 1.25s the shell/pearl begins shrinking away, finishing at 2s. Collection is recorded immediately and only once; leaving during the reveal preserves it. No second grab, sound, flash or camera motion.

Storage: `glamniverse.no-air.discoveries.v1`, JSON `{version:1, ids:[...]}`. Only known IDs restore; duplicate/invalid IDs are ignored. Pearl count derives from shell-02, 05, 08, 11, 14, 17 and 20. Corrupt/unavailable storage cannot crash the experience; when unavailable, progress is session-only. Clearing browser data removes progress; Preview hostname changes create separate storage origins. No network, analytics or cross-device sync.

The existing Left-Y menu gains one compact Ocean Discoveries panel with progress, instructions and the Glamniverse Pearl emblem at 20/20. The emblem is separate from the seven pearls. Existing three menu actions, input mapping, music and spatial anchoring remain intact. The panel redraws only when the count changes; never a permanent HUD.

Incremental upper bound: 3 opaque instanced shell draws, 11,520 shell triangles; one temporary instanced reveal draw (1,176 submitted triangles for the seven pooled pearls); one menu-only draw/two triangles. Two world materials plus one menu material, no world textures, one 1024×448 menu canvas texture (1.75 MiB, no mipmaps), zero lights, shadows, transparency or physics. Bounded twenty-instance updates; raycasts only on deliberate eligible collection attempts. Shared world teardown owns GPU disposal. Quest must judge discoverability, comfort, reach, reveal/menu readability and performance before approval.
